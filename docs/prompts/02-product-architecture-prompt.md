1. Common Project Context.
2. Phase-Specific Context.
3. Completed Reverse Engineering and Learning Document.
4. Product Architecture Design Template.

## Current feature
- Phase: [Phase number and name]
- Module: [Module name]
- Subfeature: [Subfeature name]

## What I expect
Design how my Trip Planner should solve this problem. Do not simply reproduce the reference product. Combine what I learned from the market with my product requirements.

Work through:
1. Problem and product requirements.
2. User workflows and failure paths.
3. Business rules and validations.
4. Domain model and entity relationships.
5. Database design and constraints.
6. API contracts.
7. Application layers and module boundaries.
8. Authorization and security.
9. Transactions, consistency, concurrency, and failure scenarios.
10. Integration with other modules.
11. Testing scenarios.
12. Implementation readiness and a vertical-slice plan.

Explain why each decision is appropriate and discuss alternatives where meaningful. Identify unresolved decisions instead of silently making assumptions. Keep the design consistent with an API-first modular monolith.

Do not write implementation code until the architecture is reviewed and approved. Complete the Product Architecture Design Template.
